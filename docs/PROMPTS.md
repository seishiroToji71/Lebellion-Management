# Промпты для Claude Code (вставлять по очереди, одна фаза за раз)

Перед началом: положить `CLAUDE.md` в корень репозитория, запустить `claude` в корне.
После каждой фазы: проверить, что сборка и тесты реально прошли, сделать коммит, только потом переходить дальше.

---
## Фаза 0 — каркас
```
Прочитай CLAUDE.md. Репозиторий пустой. Сначала предложи план, потом после моего OK сделай:
1. Структуру монорепо (/backend, /infra, /docs) и .gitignore.
2. Spring Boot (Kotlin, Gradle Kotlin DSL, JDK 21): актуальные стабильные версии проверь сам.
3. Подключение PostgreSQL + Flyway, первая миграция с таблицами organization, branch, unit, employee (везде organization_id).
4. docker-compose для локальной разработки (postgres) и .env.example.
5. Endpoint /health, тесты на Testcontainers, GitHub Actions: build + test.
6. docs/openapi.yaml с одним health-эндпоинтом.
Критерий готовности: `./gradlew build` зелёный, `docker compose up` поднимает БД, приложение стартует.
```

## Фаза 1 — вход и роли
```
Реализуй аутентификацию по CLAUDE.md: регистрация организации учредителем, вход учредителя (телефон/email + пароль),
вход сотрудника по invite-коду (код выдаёт учредитель или управляющий, привязка к подразделению), JWT access + refresh.
Роли FOUNDER, BRANCH_MANAGER, EMPLOYEE, проверки в сервисном слое.
Тесты: изоляция организаций (пользователь одной организации не видит данные другой), просроченные и подделанные токены.
Сначала обнови openapi.yaml и покажи мне контракт.
```

## Фаза 2 — шаблоны и расписание
```
Реализуй ChecklistTemplate/ChecklistItem и Schedule с периодичностью (несколько слотов в день, через день, раз в неделю).
Планировщик генерирует TaskInstance с due_at в часовом поясе Asia/Tashkent (в БД UTC).
Серверная задача переводит PENDING в MISSED в момент due_at. Идемпотентность планировщика обязательна (двойной запуск не создаёт дубли).
Тесты на границы: полночь, смена дня, повторный запуск.
```

## Фаза 3 — отправка фото и защита от дублей
```
Реализуй Submission: ответы Да/Нет + фото (multipart), StorageService (локальный диск, интерфейс под будущий S3),
подписанные ссылки на фото. Реализуй защиту от дублей по разделу "Duplicate / fake photo protection" из CLAUDE.md:
SHA-256 + собственный dHash, порог настраиваемый, ответ 409 DUPLICATE_PHOTO, журнал заблокированных попыток.
Добавь nullable auto_flags (jsonb) в submissions, но НЕ реализуй проверку содержимого.
Тесты: одинаковый файл, пережатый файл, слегка обрезанный файл, разные фото (не должны блокироваться).
```

## Фаза 4 — проверка, отсрочки, аудит
```
Реализуй Review (принять/отклонить с причиной; отклонённое можно отправить повторно), ExtensionRequest по правилам из CLAUDE.md
(лимиты, запрет для critical, эскалация управляющему через N часов), AuditLog (только добавление).
Предложи автомат состояний TaskInstance в виде диаграммы и таблицы переходов ДО кода, дождись моего OK.
Тесты на каждый допустимый и каждый недопустимый переход.
```

## Фаза 5 — дашборд и отчёты
```
Реализуй API для дашборда учредителя: сводка по филиалам (выполнено/пропущено/отсрочено, просрочки), рейтинг филиалов,
очередь проверки (сортировка: сначала подозрительное, затем остальное), число заблокированных дублей по сотруднику.
Еженедельный отчёт в PDF и Excel. Проверь план запросов (EXPLAIN) на 100 000 задач и добавь индексы.
```

## Фаза 6 — импорт из Excel и KPI
```
Импорт шаблонов из наших Excel-файлов (KPI_rus_6_2.xlsx — 6 листов по ролям с баллами и порогами бонуса/штрафа;
Уборка.xlsx — графики уборки кухни и зала, генуборка по неделям, зонты). Файлы положу в docs/samples/.
Реализуй KPI-аудит: сумма баллов, рекомендация по порогам из настроек шаблона. Зарплату НЕ считать.
Сначала покажи маппинг листов на модель данных и жди моего OK.
```

## Фаза 7 — деплой
```
Подготовь /infra: docker-compose для продакшена (backend, postgres, caddy), автоматические бэкапы БД и фото на вторую площадку,
Prometheus + Grafana + Uptime Kuma, пайплайн деплоя по SSH. Без Kubernetes. Напиши runbook: как восстановиться из бэкапа.
Проверь восстановление на чистой машине и опиши результат честно.
```
