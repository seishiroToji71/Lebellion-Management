# Lebellion Management — decisions log

## Phase 1 — authentication & roles (accepted)

- **Employee = no password.** Joins via a one-time invite code; uses a personal phone.
- **FOUNDER / BRANCH_MANAGER = password required** (bcrypt/argon2 via `DelegatingPasswordEncoder`).
  BRANCH_MANAGER sets the password at join; FOUNDER sets it at register.
- **`employee` table renamed to `app_user`** — one users table for all three roles.
- **`invite.target_employee_id` (nullable) = recovery invite.** For an existing user: at join the
  session binds to that user and all their previous refresh families are revoked. No duplicate users.
- **Refresh tokens (sliding, rotated):**
  - EMPLOYEE — sliding 60 days of inactivity.
  - FOUNDER / BRANCH_MANAGER — sliding 30 days of inactivity, absolute cap 90 days.
- **Session bound to `device_id`** (generated by the app at install). A refresh presented with a
  different `device_id` is treated as token theft → the family is revoked.
- **Theft detection with rotation** + a **30 s grace window** so honest offline retries do not log
  users out. Reuse of a rotated/revoked token outside the grace window revokes the whole family.
- **Invite codes stored as HMAC-SHA256** (`INVITE_HMAC_SECRET` from env), >= 40 bits of entropy,
  unambiguous alphabet (no `0/O/1/l/I`).
- **API under `/api/v1`; required `X-App-Version` header**; too-old client → `426 UPGRADE_REQUIRED`.
- Also (already in the contract): identical `401 INVALID_CREDENTIALS` for login/join; rate limiting
  on login/join/register; immediate access revocation via `token_version`; secrets from env only;
  phone normalized to E.164; `POST /auth/register` gated by `REGISTRATION_ENABLED`.

### Implementation order (а)–(д)
- **(а)** V2 migration: `app_user`, `invite`, `refresh_token`.
- **(б)** Auth core: password encoder, JWT access (with `token_version` claim), opaque refresh +
  hashing, HMAC for invite codes, device binding, rate limiter + trusted-proxy IP resolution.
- **(в)** Auth endpoints: register, login, join (+ password for managers), refresh
  (rotation / grace / theft), logout, `/me`.
- **(г)** Org & invites: branches/units, create/list/reissue invites, recovery invite,
  employees list + deactivate.
- **(д)** Tests: tenant isolation, expired & forged tokens, deactivated user → 401 immediately,
  invite reuse + brute-force, refresh reuse + family revoke, parallel refresh, `device_id` mismatch,
  rate-limit IP behind a trusted proxy.
